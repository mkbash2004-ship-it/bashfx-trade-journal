# Netlify Deployment Guide

This repository is a full-stack application. Netlify can host the compiled React/Vite frontend, but the Express/tRPC server, MySQL database, OAuth callback, file storage, AI integrations, and scheduled reminder endpoints must remain available on a separate backend service. The current application build is healthy: `pnpm check`, `pnpm test`, and `pnpm build` pass locally.

## Frontend site settings

Create a Netlify site from the `main` branch of `mkbash2004-ship-it/bashfx-trade-journal` and use the following settings. The repository now includes `netlify.toml`, so Netlify can read these values automatically.

| Setting | Value |
|---|---|
| Build command | `pnpm build:netlify` |
| Publish directory | `dist/public` |
| Node.js version | `22` |
| pnpm version | `10.4.1` |

The frontend-only script is intentional. The existing `pnpm build` also bundles the server into `dist/index.js`, which is not needed for a static Netlify deployment.

## API proxy requirement

The browser currently calls `/api/trpc` and `/api/oauth/callback` on the same origin. This is useful because it preserves cookies and avoids cross-origin authentication problems. After a backend service is deployed, add its HTTPS base URL to `netlify.toml` by inserting this rule before the final SPA fallback rule:

```toml
[[redirects]]
  from = "/api/*"
  to = "https://YOUR-BACKEND-HOST.example.com/api/:splat"
  status = 200
  force = true
```

Replace `https://YOUR-BACKEND-HOST.example.com` with the real backend URL. Do not deploy this placeholder unchanged. The API proxy must appear before the `/*` to `/index.html` rule; otherwise API requests will be served the React entry point instead of reaching the backend.

Netlify documents that a status-200 redirect acts as a rewrite, keeping the browser URL unchanged while fetching the target service behind the scenes. Its documentation also recommends the `/* /index.html 200` fallback for single-page applications [1].

## Backend requirements

The backend service must run the repository’s production command:

```bash
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

It must expose HTTPS routes under `/api/trpc`, `/api/oauth/callback`, and the scheduled endpoint paths. The backend must listen on the provider’s `PORT` value and must have access to the application’s MySQL/TiDB database and storage service.

Configure secrets in the backend provider’s environment settings, never in GitHub. The repository’s runtime map expects `VITE_APP_ID`, `JWT_SECRET`, `DATABASE_URL`, `OAUTH_SERVER_URL`, `OWNER_OPEN_ID`, `BUILT_IN_FORGE_API_URL`, and `BUILT_IN_FORGE_API_KEY`. The OAuth provider must also allow the Netlify site’s proxied callback URL, for example `https://YOUR-NETLIFY-SITE.netlify.app/api/oauth/callback`, if its configuration requires an explicit callback allowlist.

## Verification

After the backend is online and the proxy URL has been replaced, verify the site in this order: load the Netlify homepage; open a deep client-side route directly; confirm `/api/trpc` returns an application response rather than `index.html`; complete login; create a test journal entry; upload a small test asset; and confirm the scheduled reminder endpoints are invoked by the selected backend scheduler.

The pink “billing issue” banner is not generated by this repository. A Netlify deployment can avoid relying on that affected public site, but it cannot restore the current Manus deployment or move the existing database and secrets automatically.
